# 5차시 — Supabase 연동 (수준별 학습자료 변환기 확장)

2026 인공지능 활용 선도교사 후속전문연수 **5차시 「데이터 입력·저장·조회 구현」** 샘플 폴더입니다.
4차시 앱(수준별 학습자료 변환기)에 **학생의 확인 질문 답과 질문을 Supabase에 저장**하고, 교사가 **반별로 모아 보는** 기능을 더했습니다.

> **4차시와 별도로 관리하는 폴더입니다.** 4차시 폴더(`../4차시_수준별학습자료변환기`)와 git 저장소가 따로이며, 이 폴더의 변경은 4차시에 영향을 주지 않습니다.

## 현재 상태

| 항목 | 상태 |
|---|---|
| 출발점 | 4차시 앱 코드 복사본(`.env.local` 제외) |
| 테이블 SQL | `supabase/migrations/20261126113000_create_answers_questions.sql` — Supabase에서 실행해 표 2개 생성 확인. RLS 켬, 브라우저용 정책 없음 |
| 서버 함수 | `api/submit.js`(저장) · `api/results.js`(교사 조회) · `api/_store.js`(공통) — **구현, 로컬 시험 통과** |
| 학생 화면 | 반 코드·학번 입력, 채점 시 답 저장, 질문 입력 시 질문 저장 — **구현** |
| 교사 화면 | `teacher.html` — 교사 코드 확인 후 반별 답·질문 조회, 반 코드로 거르기 — **구현** |
| 시험 | 모의 시험 60개 + 실제 Supabase(로컬 서버 경유) 24개 통과, 브라우저 동작 확인 |
| 배포 | **Vercel**(화면·서버 함수) + **Supabase**(DB). 서버 함수는 Node 형식 그대로 올림. Vercel 배포는 **아직 실행하지 않음**(Vercel 계정·프로젝트 필요) |
| **아직 안 한 것** | Vercel 배포와 환경변수 5개 등록, 배포 주소에서 학생·교사 화면 확인, publishable key로 직접 접근 거부 확인, 다른 기기 확인, 교사 코드 입력 횟수 제한 |

## 기능

- 시작 화면에서 **반 코드와 학번**을 입력. **실명·연락처는 받지 않음**(반 코드는 영문·숫자·`-`만, 학번은 숫자만)
- 입력하지 않으면 저장 없이 읽기만 가능
- 형성평가 **[채점하기]** 때 문항별 답을 `answers`에 저장(점수는 저장하지 않음). 저장이 실패해도 채점 결과는 그대로이고 **[다시 저장]** 가능
- 서술형에서 **질문을 입력해** 힌트를 받으면 질문과 받은 힌트 단계를 `questions`에 저장(질문을 비운 요청은 저장하지 않음)
- `teacher.html`: 교사 코드가 서버의 `TEACHER_CODE`와 같을 때만 기록 표시. **반 코드로 거르기**, 최신순 표마다 최대 500줄
- 브라우저는 Supabase에 직접 접근하지 않음. 서버 함수만 secret key로 접근

```text

├─ api/
│  ├─ feedback.js                         # 4차시 서버 함수 — Gemini 소크라테스식 힌트
│  ├─ submit.js                           # 저장: answers / questions
│  ├─ results.js                          # 교사 조회(교사 코드 필요)
│  └─ _store.js                           # 공통: 입력 검사 + Supabase REST 호출
├─ supabase/migrations/                   # 테이블 SQL

```

## 환경변수

`.env.example`을 복사해 `.env.local`을 만들고 값을 채웁니다. `.env.local`은 `.gitignore`로 제외됩니다.

| 이름 | 용도 |
|---|---|
| `GEMINI_API_KEY` | 힌트(4차시와 같음). **`GEMINI_MODEL` 줄이 아니라 이 줄에 넣기** |
| `GEMINI_MODEL` | (선택) 비워 두면 `gemini-3.5-flash-lite` |
| `SUPABASE_URL` | Supabase 프로젝트 주소 `https://<프로젝트ID>.supabase.co` |
| `SUPABASE_SECRET_KEY` | 모든 권한 키(`sb_secret_…`). 서버 함수에서만 읽음. Publishable key가 아님 |
| `TEACHER_CODE` | 교사 조회 코드(교사가 정함) |

- **로컬**은 `.env.local`에, **배포**에서는 같은 이름·값을 **Vercel 환경변수**에 등록합니다(`.env.local`은 GitHub에 올라가지 않으므로). 환경변수를 새로 등록·변경한 뒤에는 재배포해야 반영됩니다.

## 로컬 실행

Node.js 20 이상이 필요합니다(외부 npm 패키지 설치 불필요).

```bash
npm run dev
```

- 학생 화면: `http://127.0.0.1:5173/`
- 교사 화면: `http://127.0.0.1:5173/teacher.html`
- 포트가 이미 쓰이고 있으면 `PORT=5174 npm run dev`처럼 바꿔 실행
- 시작 로그에 `SUPABASE_URL`·`SUPABASE_SECRET_KEY`·`TEACHER_CODE`가 "설정됨"인지 표시됨

## 확인하는 방법 (가상 데이터)

1. 학생 화면에서 반 코드 `1-3`, 학번 `7`을 입력하고 수준을 골라 형성평가를 채점
2. Supabase **Table Editor**에서 `answers`에 문항별 줄이 생겼는지 확인
3. 서술형에서 질문을 입력해 힌트를 받으면 `questions`에 한 줄 생기는지 확인
4. `teacher.html`에서 교사 코드를 넣어 같은 기록이 보이는지, 반 코드로 거르는지 확인
- 실습 기록은 가상 반 코드·학번으로만 만들고, 끝나면 Table Editor에서 삭제

## 보안 및 개인정보 원칙

- 키와 교사 코드는 저장소·브라우저·대화창에 쓰지 않음. 교사 코드는 주소(URL)에 넣지 않고 요청 헤더로만 보냄
- 학생 구분은 반 코드와 학번만 사용. 이름 같은 한글은 반 코드·학번 칸에서 거부됨
- 반 코드와 학번의 조합으로도 학생을 알아볼 수 있으므로 개인정보에 준하여 다룸. 실제 수업 적용 전에 학교의 개인정보 처리 절차를 확인
- 학기가 끝나면 두 표의 기록을 삭제
