# 5차시 — Supabase 연동 (수준별 학습자료 변환기 확장)

2026 인공지능 활용 선도교사 후속전문연수 **5차시 「데이터 입력·저장·조회 구현」** 샘플 폴더입니다.
4차시 앱(수준별 학습자료 변환기)에 **학생의 확인 질문 답과 질문을 Supabase에 저장**하는 기능을 더합니다.

> **4차시와 별도로 관리하는 폴더입니다.** 4차시 폴더(`../4차시_수준별학습자료변환기`)와 git 저장소가 따로이며, 이 폴더의 변경은 4차시에 영향을 주지 않습니다.

## 현재 상태

| 항목 | 상태 |
|---|---|
| 출발점 | 4차시 앱 코드 복사본(4차시 저장소 커밋 `2f128c6` 기준, `.env.local` 제외) |
| 설계 문서 | 설계명세서 10절 · PRD 5-7절 · TRD 14절 (저장 기능 설계 추가됨) |
| 테이블 SQL | `supabase/migrations/20261126113000_create_answers_questions.sql` (RLS 켬, 브라우저용 정책 없음) — **Supabase에서 아직 실행해 보지 않음** |
| 서버 함수 | `api/submit.js`·`api/results.js` — **아직 만들지 않음** |
| 화면 | 반 코드·학번 입력, `teacher.html` — **아직 만들지 않음** |

## 만들 기능 (요약)

- 시작 화면에서 **반 코드와 학번**을 입력. **실명·연락처는 받지 않음**
- 형성평가 채점 시 문항별 답을 `answers`에 저장
- 서술형에서 질문을 입력해 힌트를 받으면 `questions`에 저장(질문, 받은 힌트 단계)
- 교사 코드(`TEACHER_CODE`)를 입력하면 `teacher.html`에서 반별 기록 조회
- 브라우저는 DB를 직접 읽고 쓰지 않음. 서버 함수만 secret key로 접근

자세한 내용: [설계명세서.md](설계명세서.md) 10절 · [PRD.md](PRD.md) 5-7절 · [TRD.md](TRD.md) 14절

## 폴더 구조

```text
.
├─ index.html · css/ · js/ · materials/   # 4차시 학생 화면 (그대로)
├─ api/feedback.js                        # 4차시 서버 함수 — Gemini 소크라테스식 힌트 (그대로)
├─ api/submit.js · api/results.js         # (예정) 저장·교사 조회 서버 함수
├─ teacher.html                           # (예정) 교사 조회 화면
├─ supabase/migrations/                   # 테이블 SQL
├─ dev-server.mjs                         # 로컬 개발 서버(Node.js 20+, 외부 패키지 없음)
└─ .env.example                           # 환경변수 이름 목록(값은 비움)
```

## 환경변수

`.env.example`을 복사해 `.env.local`을 만들고 값을 채웁니다. `.env.local`은 `.gitignore`로 제외됩니다.

| 이름 | 용도 |
|---|---|
| `GEMINI_API_KEY` | 힌트(4차시와 같음) |
| `SUPABASE_URL` | Supabase 프로젝트 주소 |
| `SUPABASE_SECRET_KEY` | 모든 권한 키. 서버 함수에서만 읽음 |
| `TEACHER_CODE` | 교사 조회 코드(교사가 정함) |

## 보안 및 개인정보 원칙

- 키와 교사 코드는 저장소·브라우저·대화창에 쓰지 않음
- 학생 구분은 반 코드와 학번만 사용. 연수 실습은 가상 값(예: 반 코드 `1-3`, 학번 `7`)
- 반 코드와 학번의 조합으로도 학생을 알아볼 수 있으므로 개인정보에 준하여 다룸. 실제 수업 적용 전에 학교의 개인정보 처리 절차를 확인
